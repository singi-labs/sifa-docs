Your Sifa ID profile can also be your personal website. You have two ways to get one. Your choice depends on how much you want to build yourself.

|                 | Sifa page (ready-made)                        | Build your own                                             |
| --------------- | --------------------------------------------- | ---------------------------------------------------------- |
| **For**         | Everyone. You do not write code.              | People who write code.                                     |
| **Design**      | A fixed layout. You do not change it.         | Your own design.                                           |
| **Address**     | `page.sifa.id/{username}`, or your own domain | Your own domain                                            |
| **Data source** | Your Sifa profile, through Sifa's public API  | Your `id.sifa.*` records, from your PDS or through the SDK |

The two options use the same data. Your profile records stay on your PDS either way.

## Sifa page

Every Sifa profile has a standalone personal website at `page.sifa.id/{username}`. The layout is like [academicpages.github.io](https://academicpages.github.io/): a top masthead, a left sidebar with your identity and links, a print-friendly layout, and a dark mode toggle. It looks like your own personal site, not a social profile. For an overview, see [sifa.id/page](https://sifa.id/page).

The content comes from the same profile sections you already fill in on Sifa: About, Positions, Education, Publications, and so on. The Sifa page has no separate data entry. Update your profile once, and both views show the change.

### Self-hosting your own copy

The renderer behind this page is an open-source package, [`@singi-labs/sifa-page-renderer`](https://github.com/singi-labs/sifa-page-renderer). To run your own copy on your own domain, with your own branding, fork [sifa-page](https://github.com/singi-labs/sifa-page): a small static-site scaffold that pulls your profile from Sifa's public API and builds the same layout. It deploys to GitHub Pages or any static host.

The fastest path is GitHub Pages, straight from the fork, with no local build and no server:

1. **Fork** [sifa-page](https://github.com/singi-labs/sifa-page) to your GitHub account.
2. In the fork, open **Settings → Secrets and variables → Actions** and select the **Variables** tab. Click **New repository variable**, not an environment variable. Name it `SIFA_ID`. Set the value to your Sifa username (for example `alice.bsky.social`). A username works well. For a site that keeps working after a username change, use your [DID](/docs/dids-usernames-providers) (`did:plc:...`) instead. To find your DID, open **Settings → Account** on [sifa.id](https://sifa.id) and copy it there.
3. Open **Settings → Pages**. Set **Source** to **GitHub Actions**.
4. Open the **Actions** tab. It sits in the top row of the repository, next to **Settings**, not inside it. Run the **Deploy site** workflow, or push any commit. Your site publishes at `https://<your-username>.github.io/sifa-page/`.

The scaffold ships with the GitHub Actions workflow, so steps 3 and 4 are the whole deploy. Profile edits appear the next time the workflow runs. To keep the site current, add a scheduled trigger that rebuilds it daily.

**Your own domain.** GitHub Pages supports custom domains under **Settings → Pages → Custom domain**: add the domain and the DNS record GitHub gives you, and your site serves from `cv.alice.com` instead of the `github.io` URL. This domain serves your website. It is separate from your [Sifa username domain](/docs/use-your-own-domain).

Your profile data still lives on your PDS either way. A self-hosted page changes which host serves the HTML, not who owns the records underneath.

## Build your own

If you write code, you can build a site with your own design on your Sifa data. Your profile is a set of public `id.sifa.*` records on your PDS. Any site can read them. You do not need permission from Sifa.

You have two ways to get the data:

- Use [`@singi-labs/sifa-sdk`](https://github.com/singi-labs/sifa-sdk). It gives you types, schemas, and fetchers for Sifa data.
- Read your `id.sifa.*` records directly from your PDS. [Lexicons and integrations](/docs/lexicons-and-integrations) lists the record types. [Your data on a provider](/docs/your-data-on-a-provider) shows what a record looks like.
